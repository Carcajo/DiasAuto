# Тестовое задание DiasAuto

Автоматизированный сервис проверки и валидации номенклатуры каталога автокомпонентов на соответствие правилам масочных сертификатов соответствия (на примере сертификатов **HI-LEX CORPORATION**).

Решение позволяет выгрузить каталог номенклатуры (Excel/CSV), сопоставить артикулы с реестром разрешенных префиксов и правил масок, провести гранулярную диагностику причин несоответствий и выгрузить стилизованный Excel-отчет с разделением на принятые позиции и исключения.

## 🧠 Архитектура и логика работы

### Алгоритм валидации

Каждая строка входного файла проходит через конвейер сервиса `CertificateVerificationService` и валидатора `MaskValidator`:

1. **Нормализация полей (`SkuNormalizer`)**:
   - Удаление неразрывных пробелов (`\u00a0`, `\u202f`, `\u2007`).
   - Очистка граничных пробелов (`strip`).
   - Перевод латинских букв в верхний регистр (`translate`).
   - Для текстовых колонок (`Производитель`, `Товарная группа`): схлопывание внутренних дублирующихся пробелов и приведение к единому верхнему регистру.

2. **Проверка производителя**:
   - Строгое совпадение с нормализованным значением из конфигурационного файла (по умолчанию: `HI-LEX CORPORATION`).
   - В случае несовпадения позиция отправляется в исключения с причиной: `Несоответствие производителя: '...' (ожидается '...')`.

3. **Проверка товарной группы**:
   - Совпадение с нормализованным значением группы (по умолчанию: `тросы стояночного тормоза`).
   - В случае несовпадения: `Несоответствие товарной группы: '...' (ожидается '...')`.

4. **Проверка маски и формата артикула (Regex)**:
   - На основе конфигурации компилируется регулярное выражение: `^(?:ПРЕФИКС_1|...|ПРЕФИКС_N)[A-Z0-9]{4}$`.
   - Если строка удовлетворяет шаблону, артикул признается валидным, формируется шаблон маски вида `4VB****` и комментарий `Префикс 4VB и четыре допустимых символа`.

### Диагностика исключений

Если артикул не проходит регулярное выражение, включается диагностический анализатор `_diagnose_failure`, который выявляет точную причину отклонения:
- Пустой артикул.
- Перевод строки (`\n`, `\r`) внутри артикула.
- Наличие кириллических букв-двойников (например, русская `А` вместо латинской `A`).
- Дефис, точка или пробел внутри артикула.
- Недопустимые спецсимволы (`_LATIN_ALNUM_RE`).
- Неверная длина артикула при известном префиксе (например, `4VB123` или `4VB12345`).
- Неверная общая длина строки.
- Префикс отсутствует в реестре разрешенных масок сертификата.

### Архитектурные принципы
- **SOLID / DIP**: Бизнес-логика (`CertificateVerificationService`) абстрагирована от деталей ввода-вывода через интерфейсы `BaseValidator`, `BaseCatalogReader`, `BaseReportExporter`.
- **Stateless & Deterministic**: Нормализация и валидация детерминированы, логирование детально фиксирует каждый шаг.

## 🚀 Установка и запуск

### Способ 1. Локальный запуск (Python)

1. **Клонируйте репозиторий:**
   ```bash
   git clone git@github.com:Carcajo/DiasAuto.git
   cd <ИМЯ_ПАПКИ_ПРОЕКТА>
   ```

2. **Создайте и активируйте виртуальное окружение:**
   ```bash
   python -m venv venv

   # Linux / macOS:
   source venv/bin/activate

   # Windows:
   venv\Scripts\activate
   ```

3. **Установите зависимости:**
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. **(Опционально) Сгенерируйте демонстрационный файл каталога:**
   ```bash
   PYTHONPATH=. python -m src/create_sample.py
   ```
   Файл будет сохранен в `data/sample_catalog.xlsx`.

5. **Запустите веб-интерфейс Streamlit:**
   ```bash
   PYTHONPATH=. python -m streamlit run src/app.py
   ```
   Приложение откроется в браузере по адресу: [http://localhost:8501](http://localhost:8501).

---

### Способ 2. Запуск через Docker / Docker Compose

Проект готов к запуску в изолированном Docker-контейнере:

```bash
docker compose up --build -d
```

После старта контейнера веб-интерфейс доступен по адресу:
👉 **[http://localhost:8501](http://localhost:8501)**

Остановить контейнер:
```bash
docker compose down
```

## 🧪 Тестирование

Набор тестов покрывает валидацию правильных артикулов, краевые случаи исключений из ТЗ (кириллица, дефисы, неверная длина, пустые значения) и сквозной e2e-сценарий создания Excel-отчета.


## 🖥 Работа с приложением (Streamlit UI)
0. #Все логи будут видны в терминале после запуска приложения (python -m streamlit run src/app.py)
1. **Просмотр текущих правил:**
   В верхней части интерфейса в блоке *«Активные правила сертификата»* отображаются производитель, товарная группа, число активных префиксов и скомпилированный regex.
2. **Загрузка каталога:**
   - Перетащите файл каталога формата `.xlsx` или `.csv` в область загрузки.
   - Либо отметьте флаг *«Использовать демонстрационный каталог (data/sample_catalog.xlsx)»*.
3. **Обязательные колонки во входном файле:**
   - `Артикул`
   - `Производитель`
   - `Товарная группа`
4. **Результаты верификации:**
   - Отображаются карточки с метриками: *Всего проверено*, *Соответствуют*, *Исключения*.
   - В интерактивных таблицах доступны вкладки с детальным списком принятых позиций и исключений (с указанием точной причины).
5. **Выгрузка отчета:**
   По кнопке **«Скачать итоговый отчет (.xlsx)»** генерируется стилизованный двухстраничный Excel-файл:
   - Лист **«Соответствуют»** (синий заголовок): артикулы, ключи, производитель, группа, маска сертификата и комментарий.
   - Лист **«Исключения»** (коричнево-оранжевый заголовок): артикулы, позиция в строке и расшифрованная причина отклонения.

## ⚙️ Конфигурация правил (YAML)

Правила проверки настраиваются в файле `config/masks_hilex.yaml`:

```yaml
manufacturer: "HI-LEX CORPORATION"
product_group: "тросы стояночного тормоза"
mask_length: 7               # Полная длина артикула
prefix_length: 3             # Длина префикса
suffix_pattern: "[A-Z0-9]{4}" # Шаблон хвоста артикула после префикса
allowed_prefixes:
  - "4VB"
  - "4JB"
  - "4AB"
  # ... список остальных префиксов
```

При необходимости изменить длину маски, суффикс или список префиксов достаточно скорректировать YAML-файл без изменения исходного кода.
